# Автоматизация запроса и получения прайсов

<p align="center"><img src="assets/readme/hero.svg" width="100%" alt="Прайсы под контролем: черновики писем, проверка XLS/XLSX и история обработки"></p>

Небольшой самостоятельный offline-инструмент Python 3.11+ для подготовки ежемесячных запросов, проверки локальных ответов и сохранения исходных XLS/XLSX. Это очищенное выделение существующего ядра, а не текущая боевая почтовая система.

Ничего не отправляет. Все письма создаются только как `.eml` в `<state>/output`. Нет SMTP, IMAP, сетевых запросов, фоновых заданий, моделей или интеграции с каталогом товаров. Локальный адаптер читает один `.eml` либо файлы `new/` и `cur/` Maildir без изменения входов. Приложение не извлекает архивы на диск.

## Быстрый offline demo

Linux/macOS, Python 3.11+. Выполнять из каталога проекта:

```sh
python3 -m venv ../pricelist-venv
../pricelist-venv/bin/python -m pip install -r requirements.txt
../pricelist-venv/bin/python -B -m unittest discover -s . -p 'test_*.py' -v
../pricelist-venv/bin/python -B demo.py ../pricelist-demo --simulate-import
```

Каталог `../pricelist-demo` должен быть новым. Установка зависимостей может использовать сеть; само приложение и demo работают offline. Две pinned-зависимости нужны только для проверки старого XLS: `olefile` проверяет CFB-контейнер, `xlrd` читает книгу без Excel. XLSX и генератор примеров используют стандартную библиотеку. `openpyxl` не требуется.

Demo действительно создаёт читаемые XLSX и BIFF8/XLS, синтетические письма и JSON поставщика с адресами `.example`, запускает CLI отдельными процессами и проверяет результат. Последовательность: запрос → повтор без дубля → явная отметка отправки → напоминание → блокировка pendingDraft → отметка отправки напоминания → получение XLSX и XLS → повтор → запрет преждевременной благодарности → явное синтетическое подтверждение импорта → благодарность → повтор → статус.

Флаг `--simulate-import` означает только учебное подтверждение: настоящий importer не запускается, никакие товарные данные не импортируются. Без флага demo останавливается на RECEIVED. Полный журнал CLI: `../pricelist-demo/steps.json`; итоговый tracker: `../pricelist-demo/state/tracker.json`.

## Ручные команды

```sh
python3 -B examples.py ../my-fixtures
python3 -B pricelist.py --state ../my-state --suppliers ../my-fixtures/suppliers.json initial --today 2026-09-08
python3 -B pricelist.py --state ../my-state --suppliers ../my-fixtures/suppliers.json status
```

Скопируй Message-ID нужного черновика из вывода. После самостоятельной отправки владельцем внеси фактический Message-ID и время с часовым поясом:

```sh
python3 -B pricelist.py --state ../my-state --suppliers ../my-fixtures/suppliers.json mark-sent --draft-id '<ID-черновика@automation.example>' --message-id '<sent-request@office.example>' --sent-at '2026-09-08T09:00:00+00:00'
python3 -B pricelist.py --state ../my-state --suppliers ../my-fixtures/suppliers.json receive --input ../my-fixtures/reply.eml --today 2026-09-09
python3 -B pricelist.py --state ../my-state --suppliers ../my-fixtures/suppliers.json reminders --today 2026-09-10
```

`mark-sent` не отправляет письмо, не обращается к почте и не доказывает внешнюю отправку. Это явное утверждение доверенного владельца. Без него входящий ответ не связывается по одной похожей теме. Удаление файла черновика не заменяет `mark-sent` и не снимает pendingDraft.

## Получение, импорт, благодарность

RECEIVED означает только: подтверждены отправитель, цепочка, даты и один допустимый файл; неизменные исходные байты сохранены. RECEIVED не значит IMPORTED.

После фактического успешного импорта внешним инструментом владелец или доверенный importer создаёт JSON:

```json
{"receipt_id":"unique-import-1","message_id":"<reply@supplier.example>","supplier":"demo","cycle":"2026-09","sha256":"точный SHA-256 вложения из receive/status","status":"SUCCESS"}
```

```sh
python3 -B pricelist.py --state ../my-state --suppliers ../my-fixtures/suppliers.json ack-import --receipt ../import-receipt.json
python3 -B pricelist.py --state ../my-state --suppliers ../my-fixtures/suppliers.json thanks --message-id '<reply@supplier.example>' --today 2026-09-10
```

Подтверждение связано с Message-ID, ID поставщика, месяцем и SHA-256 оригинала. `FAILED` сохраняет неудачу в истории, не разрешает благодарность и не прекращает напоминания. Новый результат использует новый receipt_id. Сам инструмент не может удостоверить истинность внешнего импорта: это контракт доверенного подтверждения, а не криптографическая подпись importer.

`thanks` создаёт один черновик «Спасибо большое, взял в работу!» в ответ на конкретное входящее письмо, без приложений. Его ошибка не повторяет импорт. Отказы, повторные проверки и подтверждения остаются в `events` tracker.

## Повтор и статусы

- DRAFT: локальный черновик, не отправка.
- SENT_CONFIRMED_BY_OWNER: владелец явно зарегистрировал фактический ID/дату.
- RECEIVED: сохранён проверенный XLS/XLSX, ещё не импортирован.
- IMPORTED: принято явное SUCCESS-подтверждение.
- REVIEW: вход или связь требуют проверки; автоматического повтора нет.
- BLOCKED: ошибка конфигурации, целостности или выполнения команды; устранить причину, затем явный запуск.
- NO_OP: уже обработано, срок ещё не наступил или pendingDraft; внешних эффектов нет.
- ESCALATED: подготовлены и подтверждены три напоминания, четвёртого не будет.

Обычный повтор того же Message-ID и тех же байтов не меняет историю. Другие байты под прежним Message-ID сохраняются отдельно и дают REVIEW, не заменяя прежний результат. Для одного сохранённого REVIEW допускается только явная локальная перепроверка с новым UUID:

```sh
python3 -B pricelist.py --state ../my-state --suppliers ../my-fixtures/suppliers.json retry --message-id '<reply@supplier.example>' --token '73d3af3b-c193-4655-ac42-14f978882248' --today 2026-09-10
```

Нет автоматического повторения отправки, импорта и других внешних действий: их здесь вообще нет.

## Правила и ограничения

Первоначальный запрос готовится в первый понедельник-пятницу не раньше 8-го числа месяца. Рабочие дни здесь только пн-пт, без национальных праздников. Все даты сравниваются в UTC, `--today` задаётся явно. Не больше трёх напоминаний, не раньше двух рабочих дней после подтверждённой отправки предыдущего письма и создания предыдущего черновика. Пока предыдущее pendingDraft, следующее запрещено. Неполная цепочка означает REVIEW, не новое независимое письмо. Получение файла не останавливает напоминания; успешное подтверждение импорта останавливает их в этом месяце.

Конфигурация фиксируется отпечатком для выбранного state. Для изменения адресов/поставщиков используй отдельный state, не редактируй tracker вручную. JSON tracker хранит строки поставщиков/месяцев, Message-ID, подтверждения и историю событий, но не каталог товаров. Один процесс-писатель под `flock`, атомарный JSON и устойчивые имена файлов; локальная файловая система с `fsync`, hardlink и `flock` обязательна. Windows/NFS не поддерживаются. История в одном JSON не рассчитана на большие почтовые архивы.

Оригиналы и `.eml` записываются без перезаписи и с правами 0400; tracker 0600, новые каталоги 0700. Это защита от случайной перезаписи, не от владельца машины/root. Не используй общедоступный или недоверенный каталог. Для восстановления после сбоя между сохранением черновика и tracker повтор использует прежние байты и дату, без второго черновика.

Принимается ровно одно явное файловое XLS/XLSX-вложение. Inline-логотипы не считаются прайсом. CSV, ZIP-вложения, XLSM, макросы, формулы, внешние связи, вложенные объекты, подписанные OOXML и неизвестные XLS-streams отклоняются консервативно с причиной. Сохраняется оригинал всего письма, поэтому отвергнутый файл не теряется. Проверка структуры не доказывает бизнес-содержание и не является антивирусом. Лимиты описаны в SECURITY.md.

Локальный адаптер не заменяет настоящий почтовый клиент: нет IMAP, DKIM/SPF-проверки, доставки, календаря праздников, отмены черновиков, автоматического импорта и гарантий SLA. Доверенные конфигурация, state и подтверждения находятся под контролем владельца. Никогда не коммить state, письма, вложения и секреты в публичный репозиторий.
